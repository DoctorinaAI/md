# Migrating `flutter_md` from 0.2.x to 0.3.x

> **TL;DR** — If you only use `MarkdownWidget`, `MarkdownSelectionScope` and
> `MarkdownThemeData`, bump the version and you are done. Code changes are
> needed only if you implement the extension points (custom block painters,
> custom selection surfaces), rebuild quote / alert painters in a
> `MarkdownThemeData.builder`, or read `MD$Quote` / `MD$Alert` spans directly.
> SDK, Flutter and dependency constraints are unchanged.

Coming from the last pub.dev release, **0.0.8**? 0.1.0 and 0.2.0 were never
published to pub.dev. Read the [0.0.x → 0.2.x guide](0.0.x-to-0.2.x.md)
first, then this one.

The full list is in the [CHANGELOG](../../CHANGELOG.md) under
*Breaking vs 0.2.0*.

## Step 1 — Bump the version

```yaml
dependencies:
  flutter_md: ^0.3.0
```

## Step 2 — Quotes and alerts can hold nested blocks

A quote or alert whose body contains a fenced code block is now parsed into
nested blocks: `MD$Quote.blocks` / `MD$Alert.blocks` hold the children and
`spans` is **empty**. Plain quotes and alerts keep the old shape (non-empty
`spans`, empty `blocks`).

If you walk the model, handle both shapes:

```dart
Iterable<MD$Span> quoteSpans(MD$Quote q) => q.blocks.isEmpty
    ? q.spans
    : q.blocks.expand((b) => b.maybeMap<List<MD$Span>>(
          paragraph: (p) => p.spans,
          orElse: (_) => const <MD$Span>[],
        ));
```

If your `MarkdownThemeData.builder` returns a `BlockPainter$Quote` or
`BlockPainter$Alert`, either return `null` for bodies with `blocks` (the
default painter handles them) or pass the nested painters through the new
`children:` parameter, together with `blocks:` (the `MD$Quote.blocks` /
`MD$Alert.blocks` models, one per child) so selection offsets stay in sync
when a child painter exposes no selectable text. Build each child painter
with the theme returned by `BlockPainter$Quote.inheritFrom(theme, child)` to
match the default styling.

## Step 3 — Custom block painters

`BlockPainter$Quote.painter` and `BlockPainter$Alert.bodyPainter` are gone.
Both painters now mix in `MultiPainterSelectable`; read `renderedText` /
`fragments` instead, and override `fragments` rather than `selectionPainter` /
`selectionOrigin` in subclasses.

`SelectableBlockPainter` gained four members. Painters built on the
`SelectableTextBlock` or `MultiPainterSelectable` mixins inherit them; a
painter that `implements SelectableBlockPainter` directly must add:

```dart
@override
(int, TextAffinity) positionAndAffinityForLocal(Offset local) => …;
@override
Rect caretRectFor(int offset, TextAffinity affinity) => …;
@override
bool hitsRenderedTextAt(Offset local) => …; // glyph-tight hover test
@override
bool get selectionHighlightAboveCachedContent => false; // true if opaque fills
```

`ParagraphGestureHandler.hitTestInlineSpanWithPointerEvent` now returns `null`
for points outside the painter's box, and takes an optional `origin:` for text
not painted at the block origin.

## Step 4 — Custom selection surfaces

`MarkdownSelectionSurface` gained `textDirection`, `hitForGlobal`,
`hitsSelectableGlyphs`, `isLinkAtGlobal`, `caretRectFor`,
`localBoxesForRange`, `hasSelectionHandleLeaders` and
`clearSelectionHandleLayersIfLinked`. Implementations must add them; see
`MarkdownRenderObject` for the reference behaviour.

## Step 5 — Behaviour changes to check

- **Gesture starts no longer clamp.** `startAtGlobal`, `selectWordAtGlobal`
  and `selectBlockAtGlobal` ignore points outside every mounted surface. Pass
  `requireContainment: false` to keep the old nearest-surface clamping.
- **Monospace fonts.** Code renders in `Menlo` (iOS / macOS) and `Consolas`
  (Windows) with a fallback chain everywhere. Golden tests on those platforms
  will change; pin a face with `MarkdownThemeData.monospaceFontFamily`.
- **Desktop toolbar.** On macOS / Linux / Windows, drags, multi-clicks,
  `Cmd/Ctrl+A` and programmatic selection no longer pop up the toolbar;
  right-click shows it without changing the selection.
- **Hover is glyph-tight.** The I-beam and link cursor appear over glyphs
  only, not the empty gutter beside a short line.
- **`MarkdownThemeData.copyWith`** returns `MarkdownThemeData`. Overrides
  must narrow their return type.
- **`MarkdownRenderObject.updateSelection`** (internal) must run before
  `update` in `MarkdownWidget` subclasses and takes the incoming `markdown:`.

## Step 6 — New, optional

- Inline images and link icons: `MarkdownThemeData.imageResolver`
  (`MarkdownProviderImageResolver`, or your own `MarkdownImage`). With a
  resolver installed, `paragraphFromMarkdownSpans` may emit
  `MarkdownImageSpan` (a `PlaceholderSpan`) children, so a custom painter's
  `TextPainter.plainText` holds U+FFFC where the model has the alt text. Lay
  out and paint such painters with `layoutMarkdownText` /
  `paintMarkdownText`, and let the `SelectableTextBlock` /
  `MultiPainterSelectable` mixins map selection offsets.
- Edge autoscroll while selecting: `MarkdownSelectionScope.autoscroll`
  (`MarkdownSelectionAutoscrollConfig`), with `targetResolver` /
  `MarkdownAutoscrollTarget` for hosts with custom scrolling.
- Host gates on `MarkdownSelectionScope`: `canStartSelectionAt`,
  `ownsSelectionChrome`, `enableTouchGestures`, `enableTouchConsecutiveTaps`.
- `MarkdownThemeData.cursorResolver` / `MarkdownWidget.cursorResolver`.
- Right-to-left layout via `MarkdownThemeData.textDirection`.
